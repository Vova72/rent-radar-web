# Rent Radar — Mini App

Экран настройки фильтров, который открывается из бота кнопкой «🎛 Настроить
фильтры». Один файл без сборки и зависимостей: GitHub Pages раздаёт его как есть.

## Два стенда в одном репозитории

```
index.html        ← ПРОД. Открывается у живых пользователей.
dev/index.html    ← ДЕВ.  Открывается только дев-ботом.
```

**Почему папкой, а не веткой.** GitHub Pages собирает ровно одну ветку — ту,
что указана в Settings → Pages. Сделать «main = прод, test = дев» невозможно:
вторая ветка просто нигде не опубликуется. Поэтому стенды разделены путём,
а не веткой, и обе версии живут на `main`.

Соответствие ботам задаётся переменной `WEB_APP_BASE_URL` в `.env` каждого
стенда бота:

```
дев   WEB_APP_BASE_URL=https://vova72.github.io/rent-radar-web/dev/
прод  WEB_APP_BASE_URL=https://vova72.github.io/rent-radar-web/
```

Дев-версия сама показывает оранжевую плашку `DEV` в углу — она смотрит на
собственный путь, а не на флаг в коде. Поэтому «выкатить в прод» — это
буквально копирование файла, без единой правки и без риска забыть отладочный
переключатель.

## Порядок выкладки

Мини-апп и бот связаны форматом данных, и ломается эта связь молча: бот
просто игнорирует поле, которого не знает, а человек видит галочку, которая
«работает» и ничего не делает.

Отсюда правило: **сначала бот, потом мини-апп.**

```
1. В rent-radar:  git push  →  на сервере git pull && ./rr dev up -d --build
2. Здесь:         правим dev/index.html  →  git push
3. Проверяем в дев-боте
4. В прод:        cp dev/index.html index.html  →  git push
   (одновременно с выкладкой того же кода бота на прод)
```

Шаг 4 без шага 1 для прода — это и есть та поломка, ради которой всё
разделено: прод-бот старый, мини-апп новый, поля не совпадают.

## Кэш

WebView Telegram держит страницу жёстко. После пуша ты какое-то время будешь
открывать старую версию и думать, что деплой не проехал. Чтобы убедиться, что
смотришь новое: закрыть мини-апп полностью (свайп вниз, потом крестик), а не
свернуть.

## Что мини-апп отправляет боту

```json
{
  "locations": ["1090 Wien", "Graz"],
  "price":         { "min": 800,  "max": null },
  "square_meters": { "min": null, "max": null },
  "rooms":         { "min": 2,    "max": null },
  "hide_agencies": true
}
```

`null` означает «без ограничения». Это не мелочь: раньше край шкалы уезжал
своим числом, и «до 150 м²» — правый край, подписанный «150+», которого никто
не двигал — работал жёсткой отсечкой. В боевой базе так стояло 11 фильтров
из 21, и их владельцы не видели больших квартир.

`locations` пустой = вся Австрия. У районов Вены значение содержит индекс
(`"1090 Wien"`), потому что индекс бот сравнивает точно; у остальных городов
только название — бот ищет его по границе слова. Подставлять индекс городу
наугад нельзя: один город это несколько индексов.

## Языки

ru, uk, en, de — те же четыре, что и в боте. Язык приходит параметром `?lang=`
от бота; если его нет, берётся язык интерфейса Telegram, иначе английский.
Все подписи лежат в объекте `I18N` в начале скрипта.
